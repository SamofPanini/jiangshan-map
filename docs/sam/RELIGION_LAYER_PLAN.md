## 1｜定位与排序

### 1.1 定位：独立研究层，不挂在水系/交通层下

理由（结构性的，不是工程方便）：

1. **对象性质不同**。水系层的基本对象是「某时段的一条几何」（Feature＝geometry_id）；寺观层的基本对象是**机构**——一个有名称史、迁址史、宗属史、住持史的社会组织，几何只是它在某时段的一个属性。把寺观塞进 Feature 层，会把「机构连续性」偷换成「点位连续性」（迁址即被误判为两寺，同址改宗即被误判为一寺）。
2. **关系网是主体**。派系、法脉、下院、敕额、改宗都是**边**，且边本身有时效与出处；水系/交通层目前没有 Relation 对象（ROADMAP §4 明列「Event / Relation：做人物、事件关联时」再加）。寺观层正是触发这一条的读取方。
3. **与交通层的接口是叠加，不是从属**。寺观会成为交通层 Node 的候选（如运河沿岸寺院作为渡口/驿站功能节点），但这种对应应以 `site:` 相同或「同址候选」表达，不让一层依附另一层。

UI 上它和研究水系层一样：独立 SVG group、可关闭、关掉即恢复原版（沿用 P0a-3 的约束）。

- 契约 profile 不出现中国专用枚举。**朝代分期、敕额、五山十刹、子孙/十方、僧录司**等放在 `regions/cn` 的词表里；日本的本末、宗教法人包括关系放在 `regions/jp`。共享层只定义「机构属于某一制度性等级体系的某一等级（有时效）」「机构由某权力授予名号（事件）」这类**跨区域可比的抽象谓词**，区域词表把具体制度映射上去。

## 2｜数据契约：需要增补什么

### 2.1 总体做法：另立 profile，不膨胀现有 Feature 契约

现有 CONTRACT v0.2 是「水系几何 Feature」契约，严格键、`feature_type` 枚举只有水体。建议**不往里加 `temple` 类型**，而是新立一个并列的 **entity–claim profile**（暂名 `research_entities`），由同一个契约模块导出、共享以下已有规则：

- 半开区间 `[from, to)`、`from_status/to_status`（known/open/unknown）、无公元零年；
- `evidence_mode` × `review_state` × `dating_uncertainty` × `spatial_error` 四分；
- Source 记录（`source_id`、`source_kind`、`license_status`…）与 claim 的 `locator`；
- `region` 必填、区域 bbox；
- draft/release 分级。

几何只出现在 **site** 对象上，并且仍以 GeoJSON Feature 承载、走现有坐标/几何校验——这样地图显示可以复用研究图层的投影与开关。

### 2.3 谓词（关系边）——要分开的几类

**派系节点之间**（与 Japan-s-Temple 同名同义，直接沿用）：

- `part_of`：杨岐派 part_of 临济宗（有时效；分类体系本身是后世建构时，`evidence_mode` 标 `reconstructed` 并注明分类出处，如《五灯会元》的「五家」框架 vs 近代教科书的「五家七宗」）。
- `historical_name_of`：旧称→今称（多对多）。
- `lineage_successor_of`：法脉意义上的承续（派系对派系）。
- `legal_successor_of`：组织/法律实体承续（近代以后的佛教会、道教会；民国以前多半不适用）。

**人物之间**（中国侧必需，日本侧可共用）：

- `dharma_heir_of`（嗣法）：来自灯录的「某某法嗣」；**这是人—人边，不是寺—寺边**。
- `ordained_by`（剃度/受戒师）≠ `dharma_heir_of`。两者常被混为「师承」，必须分开。
- 道教：`transmitted_by`（授箓/传戒，如正一授箓、全真传戒）；龙门派的「派字」辈分谱是后出资料，按 `reconstructed` 处理。

**人物—机构**：

- `abbot_of`（住持，有时效）、`founder_of`（开山；常为后世追认，单独标证据方式）。

**机构—派系**（最容易出错的一条，单列）：

- `affiliated_with`（机构在某时段属某派）。**中国十方丛林的「宗属」往往是住持法脉的函数，不是机构的固有属性**——换一任住持即可能由临济换曹洞，或由律寺改禅寺。因此规则：没有直接史料写明该寺属某宗时，**不建 `affiliated_with`**，只由 `abbot_of`×`dharma_heir_of` 推出「候选宗属」并标 `hypothesis`；直接记载（如敕令「改为禅院」、寺志「本寺为某宗某派」）才可标 `attested`。

**机构之间**：

- `xiayuan_of`（下院/别院 → 本院；道教「下院」、佛教「下院/分院」）。
- `ancestral_seat_of`（祖庭）：几乎都是后世追认的称号，`evidence_mode` 不得高于来源本身的年代；区分「当时即称祖庭」与「后世称其为祖庭」。
- 与日本 `honmatsu` **不能等同**：江户本末是幕府统一造帐的法律隶属；中国没有全国性的同类帐册（明代僧录司体系、清代度牒/僧纲不等于本末）。中国侧不复用 `honmatsu` 谓词名，但在共享层用同一抽象「`subordinate_to`（制度性隶属）」，区域词表把 `honmatsu`（jp）、`xiayuan_of`（cn）挂到其下，并注明不可互推。

**机构—制度等级**（有时效的属性型关系）：

- `ranked_in`：五山十刹（南宋—元—明初）、明代「大刹/次大刹」、清代敕建等；值放区域词表。
- `tenure_type`：子孙庙 / 十方丛林（含「子孙十方」等过渡型）；**有时效**——寺院可由子孙改十方（「甲乙徒弟院改十方」），反之亦有。

### 2.4 事件与「同一性」规则（反例导向）

| 情形 | 建模 | 不许做 |
|---|---|---|
| 敕额改名（如某院赐额为「某某寺」） | 同一 `inst:`，新增名称段＋`evt:` 赐额事件 | 拆成两个机构 |
| 迁址 | 同一 `inst:`，换 `site:`，旧 site 保留 | 把新址坐标回填到早期年份 |
| 废毁后在原址另建、名称相同 | **默认两个 `inst:`＋一条 `idc:`**；有「重建/中兴」直接记载才合并 | 因同名同址自动合并 |
| 佛寺改道观（或反之） | 原 `inst:` 在该年 `to` 截止，或同机构换宗教属性——由史料措辞决定；两种都登记为候选，主会话裁 | 用「宗教」单值字段覆写 |
| 三教合一场所、佛道共祀、民间祠庙兼僧道住持 | `religion` 是**多值、有时效的 claim 集合**，可同时为 buddhist＋daoist；民间祠庙是否纳入是 Sam 待裁的范围问题 | 强行归一类 |
| 同名异寺（「天宁寺」「报恩寺」「开元寺」全国遍布；北宋崇宁/政和年间的天宁万寿寺、唐开元寺是敕令统一命名） | 地点＋年代双重约束才可落点 | 用名称做地名解析 |
| 同属某宗 | 只说明 `affiliated_with`，不推出两寺之间有任何边 | 由「同宗」推「法脉相承」或「下院」 |

### 2.5 不能照搬 Japan-s-Temple 的地方

1. **没有末寺帐那样的骨架资料**：日本试点能从《諸宗末寺帳》《御府内備考》批量得到「寺—本寺」边；中国侧的寺—寺边要从寺志、碑刻、方志逐条拣，密度低得多 ⇒ 试点的边数门槛要低于日本，且主体是人—人（灯录）与人—寺（住持）边。
2. **宗属的载体不同**（§2.3）：日本近世寺院的宗属较固定且有帐册；中国十方丛林随住持变。
3. **国家授予体系不同**：敕额、度牒、五山十刹、僧官，与日本寺格/本末/宗教法人不对应，只能在共享层用抽象谓词对接。
4. **人物库**：中国侧有 CBDB 可作人物外键；日本侧没有同级别的开放人物库。外键设计要允许「仅一侧有」。
5. **名称形态**：中国寺名常为「山号＋寺号」不固定、简称多（「灵隐」「天童」），且敕额前后差异大；日本侧的山号寺号相对稳定。名称对象须支持「全称 / 简称 / 俗称 / 敕额名」分型。
6. **区域时间轴**：日本侧以年号＋西历即可；中国侧须保留原文纪年（含干支、年号、改元当年），规范化规则沿用现有 `original_dating`。

## 4｜试点

### 4.1 候选 A（推荐）：南宋临安府（杭州）禅宗「五山」及其周边寺院，约 1127–1368

- **规模**：临安府及余杭（径山）境内 30–50 所寺院；其中五山（径山、灵隐、净慈、天童、育王中的杭州部分 3 所＋明州 2 所可作外延）与若干十刹。
- **为什么是它**：
  1. 资料密度高：DILA 典藏收有杭州多部寺志（灵隐、净慈、径山、天竺等——**具体哪几部有 TEI，待逐部核**），CBETA 灯录对南宋杭州住持的法嗣记载密集；
  2. 能同时检验本方案最难的三类问题：**十方丛林宗属随住持变**、**敕额改名**（如灵隐/净慈的赐额史）、**五山十刹制度等级的时效**（南宋成形、元续、明初改制）；
  3. **跨区域同图的天然样本**：径山无准师范—圆尔辨圆等中日僧侣往来，日本五山制度仿照南宋。这让「终局多区域同图」第一次有可验收的跨区域边（`dharma_heir_of` 跨 `cn`/`jp`），且与 Japan-s-Temple 能互通检验。
- **验收门槛（R2）**：
  - 机构 30–50，每个至少一条有卷页的 `existence` claim；点位允许大量 `not_located`，但已定位的必须写 `derivation` 与误差理由；
  - **10–20 条有卷页出处的派系/传承边**，其中至少：5 条 `dharma_heir_of`（CBETA 行级）、3 条 `abbot_of`（寺志或灯录）、2 条 `ranked_in`（五山十刹，出处须早于明代或注明后出）、2 条赐额/改名事件；
  - **至少 10 条「应拒绝的边」负例**，校验器或审核表必须把它们挡下：
    1. 同名异寺：两处「报恩寺」不得合并；
    2. 同宗不等于法脉相承：两个临济宗寺之间不得自动生成边；
    3. 剃度师 ≠ 嗣法师；
    4. 敕额改名不得拆成两寺；
    5. 某寺在住持 A 时为临济、在住持 B 时为曹洞——不得给该寺单值宗属；
    6. 「祖庭」称号若出自明清寺志，不得标为南宋时 `attested`；
    7. 五山名单在不同文献中不一致（南宋—元—明），不得合成一份无时效名单；
    8. 现代 Wikidata/OSM 坐标不得回填为南宋位置；
    9. 废毁后同址同名重建，未见「重建」直接记载时不得合并；
    10. 跨区域边：日本僧「入宋参某师」≠「嗣法某师」。
- **R0 后的修订**（2026-11-05）：
  - 等级体系同时建「禅院五山十刹」与「教院五山十刹」（同一出处同段并列）；律院按原文记为「不在其列」，不建等级边。
  - 导入顺序按 DR 建议：《咸淳临安志》寺观门（同时代）→ DILA 杭州寺志（后出，记转引链）→ CBETA 住持/法嗣 → 最后才接 DILA Place、CHGIS、Wikidata、OSM 作为地点候选。证据方向始终是「史料 → 实体假说 → 现代外键」。
  - 《乾道临安志》现存仅三卷、《淳祐临安志》按佚书处理（DR 称，未核），不作主数据。
  - DR 的估计（机构 30–50、边 15–30）只是估计，不作为验收数字；验收仍按下列门槛。
- **主要风险**：杭州寺院多次毁于兵火与迁移，南宋位置大多只能锚到「西湖某山某坞」级别；寺志多为明清编纂，对南宋事实是二手——须在 claim 里写「来源年代晚于事件」。

### 4.2 候选 B（差异大）：金元全真道关中—晋南宫观网，约 1167–1368
