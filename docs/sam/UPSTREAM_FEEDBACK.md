# 江山时序｜给上游的反馈候选（outbound）

> 建立：2026-10-23（Sam's Agent(Opus-5.5)）。本文件收集**本 fork 工作中发现的、与上游代码或数据有关的问题**，供日后统一整理成 issue / PR。
> 方向说明：[UPSTREAM_TRACKING.md](./UPSTREAM_TRACKING.md) 管"上游 → 本 fork"的吸收；本文件管"本 fork → 上游"的反馈。
> 本 fork 自己代码里的 bug（`scripts/sam/`、`js/sam/`）不收在这里，记在各自的审核件与执行报告里。

## 0｜提交规程

每条反馈在真正提交前必须：

1. **对最新 upstream HEAD 重新核实**（行号、数据会变）；把核实时的 SHA 写进该条。
2. **查重**：在上游 issues / PR 里搜一遍，已有就改为在原 issue 下补充或放弃。
3. **区分类型**：`bug`（行为错误）／`test-gap`（测试缺口）／`data-question`（史地数据存疑，附出处，不下结论）／`enhancement`（建议）。`data-question` 只提问与给出处，不替上游裁定史实。
4. **附可复现证据**：命令、输出、数据位置；我方已有解决路径的附上（指向本 fork 的提交）。
5. **由 Sam 逐条批准后再发**（向他人仓库发 issue/PR 是对外发布）。起草可派 Codex（Luna / Terra），提交动作在 Sam 批准后执行。

状态取值：`候选`（已记录未复核）→ `已复核`（对最新 HEAD 核过）→ `待批准` → `已提交`（附链接）／`放弃`（附理由）。

## 1｜条目

### UF-01｜data-question｜黄河分期年份与常见参考图不一致
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：`js/china_geo_data.js` 的 `HYDRO_DATA` 中黄河干流切换年为 11 / 1048 / 1194 / 1855（另有支流区间 [1048,1194)、[1194,1580)）。常见参考图的分期不同：
  - 中文维基风格示意图：前602 / 11 / 1048 / **1128** / **1368** / 1855；
  - 钮仲勋等编《历史时期黄河下游河道变迁图》（1994）：列 23 条分段河道，其中「南宋建炎二年河道（1128–1194）」「金大定八年河道（1168–1234）」等。
- 问：1194 作为"夺淮"切换年的依据是什么？是否考虑在数据或文档中注明所采分期方案及出处？
- 证据：`docs/sam/audit/P0a-1_INVENTORY.md`（28 条带年代条目表）；参考图出处核查见 `docs/sam/audit/P0b_huanghe_1938_sources.md`（进行中）。

### UF-02｜data-question / enhancement｜缺 1938–1947 黄河改道阶段
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：黄河最后一段为 [1855, 至今)，1938 年花园口决堤至 1947 年堵口复归期间没有独立阶段；该时期地图上仍显示 1855 年后的河道。
- 我方路径：本 fork 正在以独立研究图层做这一段的考证与演示（ROADMAP P1），完成后可把"资料出处 ＋ 几何 ＋ 年份边界测试"整理给上游参考。
- 证据：`docs/sam/audit/hydro_inventory.json` 中 `river:Huang:84327c8013cf`（[1855, null)）。

### UF-03｜test-gap｜水系校验不在边界年采样
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：`scripts/validate_atlas.js` 对黄河的断言只在 -200 / 500 / 1100 / 1500 / 2000 五个年份检查"恰好 4 段干流可见"，任何切换年（11、1048、1194、1855 等）及其前一年都没有测试；半开区间的端点若被改错一年，现有测试发现不了。
- 我方路径：`scripts/sam/hydro_inventory.js` 已能机械列出全部边界年（`coherence_probe.json` 的 `boundary_years`，33 个，含 `9999` 哨兵标注）。可建议上游在每个边界年 `y` 与 `y-1` 各断言一次可见集合。

### UF-04｜enhancement｜水系条目没有稳定 ID
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：`HYDRO_DATA.rivers` 有 10 条同名 `Huang`、没有 `id`；`_hydroMask`（`js/app.js` 约 1127 行）按数组位置拼接可见性串。运行时无问题，但外部工具或扩展无法稳定引用某一条（例如"这条研究要素替代哪一段旧河道"）。
- 我方路径：本 fork 用内容指纹生成 `legacy_id`（`scripts/sam/hydro_inventory.js`），并在上游数据变动时检测漂移。可建议上游在 `HR` 数组里加一个稳定 `id` 字段。

### UF-05｜enhancement｜水系与交通线的时间区间语义不一致
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：水系是半开区间 `[appear, vanish)`（`js/app.js` 约 1119 行）；`CORRIDOR_DATA` 是闭区间 `[span[0], span[1]]` 且用 `9999` 表示至今（约 1906 / 1914 / 2550 行）。两者都自洽，但没有文档说明，跨图层比较时容易差一年。
- 建议：在 README 或数据注释里写明两种语义；或统一为一种。

### UF-06｜enhancement（低优先）｜`?v=` 统一断言对扩展脚本不友好
- 状态：候选（核实 SHA：`a9cd67c`）
- 现象：`scripts/validate_atlas.js` 约 429–435 行要求 `index.html` 中所有 `?v=` 与 `js/app.js` 一致；第三方扩展脚本若带自己的版本号即失败。本 fork 的处理是扩展脚本不带 `?v=`。
- 是否值得反馈：低，可能不提交。
