## 3｜判断（n=1/臂·只对"右起竖横混排的旧军用图与公文书"这一形状成立）

1. **两代都选的话，选 `gpt-6-luna` high**：成本与墙钟持平（裁图条上 6-luna 快一倍），质量明显更好。它更守读序规则，`[字?]` 标得更勤，捏造也略少。这与 2026-09-24 文本单上"6-luna 慢 2.9 倍"的读数不冲突——任务形状不同。
2. 🔴 **Luna 不能单独承担关键字段**（日期、图番、图幅名、文书编号）。最需要的那个日期，两代、两种裁法，四次都错，确信度却都自评"中"，而且错法各不相同。**模型自评的确信度不能当闸门。**
3. 两臂错法多半不同 ⇒ **双读加比对能暴露大部分错误**：件名、发文日期、比例尺、7月11日注记、部外秘，两臂一致且都对；关键日期与图番两臂不一致，且至少一臂错。**但有一例一致而错**：两臂都把 img3 的「開封」写进 img2 的地名，也就是同一包里多张图会互相串内容。⇒ 一致只能作分流（"不必优先复核"），不能当正确；同一张图的内容要单图单问，或者在 prompt 里要求每条注明出自哪张图。
4. 主会话读一条图题裁图（约 2000×220 显示）的成本很低，且本 PoC 金标就是这样读出来的。⇒ **关键字段由主会话读裁图**，Luna 做量大、可容错的部分。
